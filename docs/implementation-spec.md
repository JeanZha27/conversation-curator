# 首次实施规格

## 项目任务卡

- 项目名称：Conversation Curator（对话治理工具）
- 一句话产品目标：在默认离线、原始导出只读的前提下，把 ChatGPT 导出转换为可复核的本地分类报告。
- 目标用户与场景：需要整理大量 ChatGPT 历史对话、但不希望上传原文的个人用户。
- 本轮首个用户任务：用户选择 `conversations.json`，在终端预览本地扫描和启发式分类结果，并显式导出 JSON 报告。
- 成功条件：有效输入能够产生不包含消息正文和敏感原值的结构化结果；无效输入被明确拒绝；源文件哈希在运行前后不变。
- 项目目录：`conversation-curator/`
- 当前状态：已有项目；CLI 最小纵向闭环和面向最终用户的 Codex Skill 入口已存在，本轮继续增量维护。
- 需求资料：`../conversation-curator-mvp/` 及用户提供的《对话治理 Skill：MVP 技术实现方案 v1.0》。
- 目标平台：本地命令行。
- 技术栈：TypeScript、Node.js 标准库；不引入第三方运行时依赖。
- 支持环境：本轮在 Node.js 24.19.0、macOS 上验证。
- 修改范围：仅 `conversation-curator/`。
- 已授权外部动作：无。
- 本轮明确不做：Web UI、本地服务、SQLite、账户、云同步、远程模型、平台写入、CSV/Markdown/HTML、批次回滚和部署。
- 必须保持的契约：默认零网络、零遥测；源文件只读；扫描先于分类；原始正文和敏感原值不进入报告或日志。

## 本轮需求

- `REQ-001`：CLI 必须在运行时校验输入路径、扩展名、文件类型、非空状态、256 MiB 文件上限、50,000 条对话上限和 8 MiB 单项上限。
- `REQ-002`：顶层 JSON 数组必须增量读取，不得一次加载整个导出；不得修改、移动或重命名源文件。
- `REQ-003`：适配器必须优先沿 `current_node` 父链读取当前分支；缺失当前节点时采用有标识的安全降级。确定性扫描覆盖该分支全部文本，分类上下文仅使用经硬敏感规则和完整输出隐私规则脱敏后的首三条和末三条文本，且单条标题或消息最多保留 32 Ki 字符首尾上下文。
- `REQ-004`：私钥头、常见令牌、密码字段、身份证校验位和银行卡 Luhn 规则必须在分类前扫描；只输出类型和数量。附件仅扫描文件名、内容类型等白名单元数据，不读取附件正文、二进制、图片或音频内容。
- `REQ-005`：真实本地启发式分类器必须产生固定枚举结果，并由独立运行时校验器验证；不合法结果进入失败记录。
- `REQ-006`：终端预览必须区分建议接受、需人工复核、重复和解析失败，不显示原始正文或敏感原值。
- `REQ-007`：只有 `--write --output <path>` 才写报告；逐条写入 JSON 事件数组，采用同目录临时文件和原子替换，失败或取消时清理临时文件。
- `REQ-008`：JSON 报告不得包含消息正文、原始标题、源对话 ID 或敏感匹配原值；全部输出字符串必须经过最终扫描，隐私断言由扫描结果产生。
- `REQ-009`：默认运行链路不得发起网络请求、遥测或平台写操作。
- `REQ-010`：错误必须带稳定代码、可操作说明和非零退出状态；`SIGINT` 以取消状态退出。
- `REQ-011`：报告 Schema `1.3` 的汇总必须显式标识当前分支、分支降级、内容不可用和分类文本截断数量；空结果不得以成功状态退出。
- `REQ-012`：Codex Skill 应调用 `--summary-only`，仅让汇总计数进入工具回显；详细报告必须由用户指定本地输出路径，且 Skill 不将报告内容读入模型对话。

## 路径行为

- 正常：有效数组 → 增量解析 → 规范化 → 扫描 → 分类 → 校验 → 预览 → 可选原子导出。
- 空状态：空文件、空数组或没有可分类项时明确报告，不伪造成功结果。
- 错误：缺失文件、非 JSON、非数组、超限文件和结构错误均拒绝并给出安全错误位置，不回显内容。
- 恢复：用户可修正路径或输入后重试；输出已存在时需显式 `--force`。
- 取消：关闭读取流，不留下报告临时文件。

## 验收案例

- `AC-001`：合成的标准导出包含一个正常对话，得到通过 Schema 校验的分类结果。
- `AC-002`：缺失标题和空消息的对话进入人工复核，但流程不中断。
- `AC-003`：非数组 JSON 或不存在的输入被拒绝，且不生成报告。
- `AC-004`：合成敏感模式被标记为 `S3`，报告和终端不出现原值。
- `AC-005`：重复对话 ID 被计数；第二项仍完成确定性敏感扫描，但跳过分类。重复输入使 CLI 返回部分完成状态（退出码 2），不能报告为完整成功。
- `AC-006`：完整 CLI 链路显式写出 JSON，源文件运行前后 SHA-256 相同。
- `AC-007`：不传 `--write` 时只预览，不产生输出文件。
- `AC-008`：密钥分别注入 ID、文件名、错误、标签和分类字段后，输出不包含原值。
- `AC-009`：CLI 在空格、中文、Unicode 符号和符号链接路径下正常执行。
- `AC-010`：50,000 条合成对话的完整流式闭环峰值 RSS 不超过 256 MiB。
- `AC-011`：脱敏真实导出仅从 `.private-test-data/conversations.json` 读取，不生成报告或明细日志；文件缺失、空结果或部分失败时保持发布阻塞。
- `AC-012`：七条消息当前分支的第四条包含合成密钥时必须升级为 `S3`，但第四条的分类关键词不得进入首尾采样上下文。
- `AC-013`：附件文件名中的合成密钥必须进入确定性扫描；附件正文中的合成哨兵不得进入扫描、分类或报告。
- `AC-014`：路径兼容测试只能复制运行 CLI 所需的白名单文件，不得递归复制 `.git`、`.private-test-data` 或整个项目。
- `AC-015`：邮箱、电话、POSIX/Windows 路径和 `file://` 本地资源不得原样进入分类上下文；带中文路径提示词的紧邻绝对路径也不得通过最终输出扫描，同时普通相对路径不得被误判。
- `AC-016`：附件元数据只读取附件对象和 `metadata.attachments` 项的直接白名单字段，不递归进入 `data`、`payload`、`body` 或其他正文容器。
- `AC-017`：处理完成后、原子提交前收到 `SIGINT` 时必须返回 130，且目标报告和临时文件均不存在。
- `AC-018`：取消后的临时文件删除失败时不得声称无残留；必须返回稳定的 `OUTPUT_CLEANUP_FAILED`，提示人工清理且不回显路径或底层文件错误。
- `AC-019`：无 `--force` 时，即使目标文件在检查后、提交前被创建，也不得覆盖该文件。
- `AC-020`：跨文本分片的密钥、隐藏消息和非对话角色仍进入安全扫描，但隐藏消息和非对话角色不得进入分类上下文。
- `AC-021`：接近 8 MiB 的单条消息不得导致扫描器栈溢出；分类上下文必须有界并进入强制复核，同时完整文本仍接受确定性扫描。
- `AC-022`：`--summary-only` 的 CLI 和安装包运行结果均不回显逐条对话引用或建议标题，汇总计数保持可用。

## 模拟与未决问题

- 公开回归测试输入全部为合成数据；本地另有一份不入库的真实导出结构脱敏副本完成兼容检查。
- 分类器是实际运行的本地规则实现，不是固定成功值；分类准确率尚未校准。
- 已有脱敏样本只覆盖一份导出的结构；更多导出版本、真实形态的近上限性能和分支语义仍需验证。
- 合成样本只验证兼容检查工具自身；`AC-011` 另由不入库的脱敏结构副本验证。
- 数据库存储、加密、回滚、本地 API 鉴权和 Web UI 均保持未决，不在本轮冻结。
